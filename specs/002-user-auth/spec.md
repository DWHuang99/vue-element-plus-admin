# Feature Specification: 注册功能第一阶段（用户认证）

**Feature Branch**: `002-user-auth`

**Created**: 2026-08-05

**Status**: Draft

**Input**: User description: "实现注册功能第一阶段：基础注册、密码登录、退出与必要的服务端会话管理（不含验证码、不含邮箱所有权验证、不含角色权限授权），并接线前端认证相关页面。参考已批准设计文档 docs/superpowers/specs/2026-08-05-registration-phase1-design.md"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 注册新账户并进入系统 (Priority: P1)

作为项目用户，我希望使用用户名和密码注册新账户，注册成功后无需再次登录即可直接进入系统，
以便我能立即开始使用基于真实用户身份的功能。

**Why this priority**: 注册是用户身份体系的入口；没有注册能力，登录和会话管理都无从谈起。

**Independent Test**: 在全新环境中通过注册页面提交新的用户名和密码；系统创建账户并返回有效会话，
用户无需登录即可访问需要身份验证的页面，且用户名在后续登录中有效。

**Acceptance Scenarios**:

1. **Given** 用户提供符合规则的用户名（3-32 个字符，字母/数字/下划线）和密码（至少 8 个字符），
   **When** 用户提交注册，**Then** 系统创建账户并授予有效会话，用户直接进入已登录状态。
2. **Given** 提交的用户名已被占用，**When** 用户提交注册，**Then** 系统返回明确的冲突提示，
   且不会泄露任何现有账户的敏感信息。
3. **Given** 提交的用户名或密码不符合规则，**When** 用户提交注册，**Then** 系统返回机器可读的
   字段校验错误，指明具体问题字段与原因。
4. **Given** 用户在短时间内连续发起注册请求，**When** 请求频率超过允许范围，**Then** 系统返回
   限流响应，防止批量注册滥用。
5. **Given** 注册页面已存在且当前使用模拟数据，**When** 用户提交真实注册，**Then** 页面使用
   真实后端能力完成注册并进入系统。

---

### User Story 2 - 登录已有账户 (Priority: P2)

作为已注册用户，我希望使用用户名和密码登录系统并取得有效会话，以便恢复我的登录状态并使用受保护功能。

**Why this priority**: 登录是注册后的核心复用路径，是会话管理的基础场景。

**Independent Test**: 使用一个已注册账户的正确凭据登录；系统返回有效会话并可访问受保护资源；
使用错误凭据则返回统一失败响应。

**Acceptance Scenarios**:

1. **Given** 用户提供正确且未过期的凭据，**When** 用户提交登录，**Then** 系统返回有效会话，
   用户可访问需要身份验证的资源。
2. **Given** 用户提供错误密码或提交不存在的用户名，**When** 用户提交登录，**Then** 系统返回
   相同的失败响应，不区分"用户名不存在"与"密码错误"，防止账户枚举。
3. **Given** 用户在短时间内针对同一账户或来源连续失败尝试，**When** 尝试频率超过允许范围，
   **Then** 系统返回限流响应，防止暴力破解。
4. **Given** 登录页面当前使用模拟数据，**When** 用户提交真实登录，**Then** 页面使用真实后端
   能力完成登录并恢复会话。

---

### User Story 3 - 退出并维护安全会话 (Priority: P3)

作为已登录用户，我希望能够主动退出登录使当前会话立即失效，并确保系统对会话的过期、撤销与
重放有明确的防护规则，以便我的身份凭据在退出或过期后无法被继续使用。

**Why this priority**: 安全的会话生命周期是"身份安全优先"宪章原则的核心；退出与失效机制防止
凭据被长期滥用。

**Independent Test**: 登录后主动退出，随后使用原会话凭据访问受保护资源；请求被拒绝。
系统对已过期或被撤销的会话凭据始终返回一致的拒绝结果。

**Acceptance Scenarios**:

1. **Given** 用户持有有效会话，**When** 用户执行退出，**Then** 当前会话立即失效，后续使用
   原会话凭据的请求被拒绝。
2. **Given** 会话已超过有效期，**When** 使用该会话凭据访问受保护资源，**Then** 系统返回一致的
   认证失败结果。
3. **Given** 请求缺少认证凭据或凭据格式无效，**When** 访问受保护资源，**Then** 系统返回一致的
   认证失败结果，不泄露内部错误细节。
4. **Given** 用户通过受保护接口查询当前身份，**When** 凭据有效，**Then** 系统返回当前用户
   信息；凭据无效则返回认证失败。

### Edge Cases

- 用户名包含空白字符、非法字符或超长/过短时，必须按无效输入处理并返回字段校验错误。
- 密码为空白、超短或超长时，必须按无效输入处理。
- 同一会话凭据在退出后被重复使用时，每次都必须被拒绝，不得出现间歇性放行。
- 会话在用户处于操作中间过期时，前端必须将用户引导回登录页，且不丢失安全性。
- 并发登录同一账户时，各自会话独立有效，退出其中一个不影响另一个。
- 认证失败、限流、冲突等错误响应不得包含密码、令牌、堆栈或内部路径。
- 登录/注册接口被高频调用时，限流不得产生持久化副作用或明显资源累积。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 允许用户使用用户名和密码注册新账户。
- **FR-002**: 系统 MUST 强制用户名唯一；提交已占用用户名时返回明确的冲突结果。
- **FR-003**: 系统 MUST 以安全形式存储密码，禁止明文、可逆加密或普通摘要；每个账户的密码
  存储 MUST 使用独立随机盐。
- **FR-004**: 系统 MUST 允许用户使用用户名和密码登录，并返回可用于访问受保护资源的会话凭据。
- **FR-005**: 系统 MUST 在登录失败时返回统一的失败结果，禁止泄露账户是否存在的信息。
- **FR-006**: 注册和登录接口 MUST 对请求频率进行限制，防止批量注册与暴力破解。
- **FR-007**: 每个会话凭据 MUST 具有明确的有效期，并在过期后失效。
- **FR-008**: 用户 MUST 能主动退出登录；退出后原会话凭据立即失效。
- **FR-009**: 受保护资源 MUST 拒绝缺少凭据、凭据无效、已过期或已撤销的请求，并返回一致的
  认证失败结果。
- **FR-010**: 认证接口 MUST 对输入进行校验，并返回稳定、机器可读的错误码。
- **FR-011**: 认证相关日志与错误响应 MUST NOT 包含密码、完整令牌、会话秘密或内部实现细节。
- **FR-012**: 前端登录、注册与退出流程 MUST 使用真实后端能力，替换当前模拟数据实现。
- **FR-013**: 会话凭据 MUST 以仅服务端可验证的方式存储，即使存储被泄露，凭据也不得被直接
  用于伪造会话。
- **FR-014**: 认证失败、限流与冲突等安全事件 MUST 具备可审计的记录，且记录内容遵守隐私最小化。

### Key Entities *(include if feature involves data)*

- **用户账户 (User Account)**: 代表一个可认证的身份。关键属性：唯一用户名、安全存储的密码凭据、
  创建与更新时间。与"会话"为一对多关系。
- **会话 (Session)**: 代表一次已认证的登录。关键属性：会话凭据（服务端仅存可验证形式）、
  所属用户、创建时间、有效期、撤销时间。与"用户账户"为多对一关系。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 一名新用户能够在 2 分钟内完成注册并进入系统，全程无需修改代码或配置。
- **SC-002**: 已注册用户在凭据正确时，能够在 5 秒内完成登录并访问受保护资源。
- **SC-003**: 针对同一账户的连续错误登录尝试达到阈值后，后续尝试被限流；错误尝试响应无法
  被用来区分账户是否存在。
- **SC-004**: 用户执行退出后，原会话凭据的后续请求 100% 被拒绝。
- **SC-005**: 即使存储介质发生泄漏，泄漏数据中无法还原任何账户的明文密码，也无法直接伪造
  可用会话。
- **SC-006**: 前端认证流程切换为真实后端后，注册、登录、退出三类核心场景验收通过率 100%。
- **SC-007**: 认证相关错误响应中秘密泄露数量为零（密码、令牌、内部路径）。
- **SC-008**: 在本地验收中，认证接口的成功与失败响应在 1 秒内返回可判定结果。

## Assumptions

- 注册与登录使用用户名（非邮箱）作为登录标识；邮箱字段不在本阶段引入（邮箱所有权验证属于
  后续阶段）。
- 本阶段不含验证码、邮箱验证、密码找回、OAuth/OIDC/SSO、角色权限授权与刷新令牌机制。
- 会话凭据由客户端保存并在请求中携带；具体保存与携带方式由规划阶段结合前后端分离场景决定。
- 前端角色、权限与菜单等非认证接口在本阶段保持模拟数据，仅在后续授权功能中迁移。
- 系统面向单实例部署；限流基于单实例内存即可满足本阶段需求。
- 注册成功即视为登录成功，用户无需在注册后再次登录。
